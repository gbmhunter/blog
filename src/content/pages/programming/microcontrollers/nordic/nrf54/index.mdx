The _nRF54 Series_ is a family of SoCs by Nordic Semiconductor designed to supersede the [nRF52 series](/programming/microcontrollers/nordic/nrf52/). Some of the core features of this family are a low power multi-protocol 2.4 GHz radio, a 128 MHz Arm Cortex-M33 CPU and ultra low-energy operation. Within the nRF54 family there are two sub-families, the nRF54H and nRF54L series.[^nordic-semi-nrf54l-series-ds]

The nRF54 series has good support for using the [Zephyr framework](/programming/operating-systems/zephyr/) to develop the firmware, as it is officially backed by Nordic Semiconductor. Zephyr provides an RTOS, peripheral drivers and utility API. There are many project examples and guides available for using Zephyr with the nRF54.

## nRF54L Series

<Image src={import('./_assets/nrf54l15-qfn-photo.webp')} width="200px">A photo of the nRF54L15 SoC in a 6x6 mm QFN package.[^nordic-semi-nrf54l15-product-page]</Image>

<Image src={import('./_assets/nrf54l-internal-architecture-block-diagram.webp')} width="500px">The internal architecture block diagram of the nRF54L series SoC.[^nordic-semi-nrf54l-series-ds]</Image>

The nRF54L series launched with three SoCs, the nRF54L15, nRF54L10 and nRF54L05 (excluding package type, there are a number of suffixes on each of these to denote the package type). They differentiate themselves by having different amounts of RAM and NVM memory. The series has since grown to include parts such as the larger nRF54LM20A. Note that we can't really call the NVM [flash](/electronics/components/memory/flash/), as Nordic uses RRAM (resistive random access memory) for the NVM.

<Aside type="tip">
Aside from being cheaper, SoCs with less RAM also have lower power consumption, because each additional RAM block requires a small amount of quiescent current. For example, the nRF54L15 with 256 kB RAM draws $2.9\unit{\mu A}$ when in sleep, whilst the nRF54L05 with only 96 kB of RAM draws $1.7\unit{\mu A}$ in sleep.[^nordic-semi-nrf54l-series-ds]
</Aside>

### Tamper Detection

The nRF54L series SoCs have a built-in tamper controller called `TAMPC`. This tamper controller can do the following:

- Detect internal timing glitches to protect against fault injection attacks such as voltage spiking or electromagnetic fault injection (EMFI).
- Detect external tampering via sending a PRBS (pseudo-random bit sequence) pattern to an output pin and making sure the same pattern is received on an input pin (this is designed to be connected to an external tamper shield which detects when the product is broken into).
- Detect if tampering occurs during AES and IKG operations (the `CRACEN` detector).

<Image src={import('./_assets/nrf54l-tampc-internal-block-diagram.webp')} width="400px">The internal block diagram of the TAMPC.[^nordic-semi-nrf54l-series-ds]</Image>

### LFXO

If you need higher accuracy than the internal RC oscillator provides for a LF clock, you can fit an external $32.768\unit{kHz}$ [crystal](/electronics/components/crystals/) and use the LFXO (low frequency crystal oscillator) peripheral.

<Image src={import('./_assets/nrf54l-lfxo-circuit-diagram.webp')} width="400px">The circuit diagram (internal and external) for the LFXO peripheral. You can see the adjustable internal capacitors.[^nordic-semi-nrf54l-series-ds-v1-key-features]</Image>

Interestingly, you don't normally have to fit the typical load capacitors as the nRF54L series has internal adjustable load capacitors (it also has them for the high-frequency oscillator, HFXO). They are adjustable by firmware in the range $3\text{–}18\unit{pF}$ (inclusive) in steps of $0.65\unit{pF}$.[^nordic-semi-nrf54l-series-ds-v1-key-features]

Instead of connecting a crystal, you can also drive the LFXO with an external clock signal. In this case, connect the 32.768 kHz clock signal to the XL1 pin and leave the XL2 pin unconnected. Then in firmware set `XOSC32KI.BYPASS=Enabled.`.[^nordic-semi-nrf54l-series-ds-v1-key-features]
